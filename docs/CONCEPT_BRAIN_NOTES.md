# 按 concept-brain 架构做"看画面 → 按键"的实测记录

日期：2026-11-05
依据：`leeR1ven/concept-brain` 的 `docs/ARCHITECTURE.md`、`docs/THEORY.md`、`docs/EQUIVALENCE.md`（均已读）。
原则：只用一条局部赫布规则（时序、协方差形式、凹形增长 + 统一降权），**没有反向传播**。

## 一、实现（`experiments/p51_screen2key.py`、`p62_core.py`、`p64_play8.py`、`p65_curriculum.py`）

| 部分 | 做法 |
|---|---|
| 输入 | 8×8 画面 → 每像素 4 级温度计正反对（每像素恰亮 2 格，共 128 格亮 / 512 总） |
| 中间层 | 三层固定随机网络，每个神经元接附近 8 个输入，门槛取自身输入的 70% 分位 |
| 最后一层 | 每拍挑最强 top-m，m = 第一层亮的数量（架构规定） |
| 学习 | 时序赫布，协方差形式（两侧减平时水平），凹形增长 `η·a·b/(1+w/w_ref)^pow` |
| 决策 | 对每个候选动作算最后一层，预测"这一步之后会不会死"，选风险最低的 |

## 二、四个排查（每个都有数字，且前三个曾把我误导）

| 排查 | 结果 | 结论 |
|---|---|---|
| ① 物理可玩性 | 提前 1~2 格起跳存活 **0%→100%**（改跳跃参数后） | **曾经游戏本身跳不过去**；不修就永远"学不会" |
| ② 表示可区分 | 线性探针：8×8 = **1.000**，16×16 = **0.556** | 分辨率**不是越高越好**：最后一层容量固定，坑在 16×16 里只占 12.5%，信息被稀释 |
| ③ 重叠量法 | 含公共背景时 c/o=1.26；去掉公共部分后 **c/o=3.94** | 必须按 `THEORY §2.2` 去掉"什么都亮"的部分再量 |
| ④ 动作空间 | 见下表 | 动作越多越需要"情境门控" |

## 三、动作空间与门控（本轮最关键的结论）

固定 3 个坑的关卡：

| 配置 | 最远 x | 局数 |
|---|---:|---:|
| 2 动作（前进 / 前进+跳） | **3291** | 18 |
| 3 动作（+ 原地跳），无门控 | **33.5** | 187 |
| 3 动作 + 门控 0.5 | 2271 | 78 |
| 4 动作 + 门控 1.0 | 2509 | 17 |
| 不跳（基线） | 5.5 | — |
| 随机按键（基线） | 5.5 | — |
| 脚本"会玩的人" | 301 | — |

**门控**：预测"不危险"时，只允许"往前走"的动作（原地跳、不动被禁止）；预测"危险"时全部放开。
这是架构里"很少一起亮的神经元互相抑制"在执行层的实现。

**结论**：只有一条赫布规则时，动作空间一大就崩（3291 → 33.5）；加门控后 4 个动作也能回到 2500 米级。

## 四、泛化（随机关卡）

坑位每局随机（间隔 10~16 格、宽 2 格）：

| 配置 | 最远 x | 局数 |
|---|---:|---:|
| 2 动作 | 1612 | 95 |
| 4 动作 + 门控 1.0 | **2046** | 93 |

**固定关卡能过可能是背位置；随机关卡也能过，才说明它真的在看画面。**

## 五、凹形增长的作用（真实马里奥数据，2547 帧）

| 键 | 线性增长 | **凹形增长** | 基线 |
|---|---:|---:|---:|
| right | 0.740 | **0.947** | 0.659 |
| A（跳） | 0.222 | **0.555** | 0.815 |
| B（跑） | 0.942 | 0.932 | 0.736 |
| 总体 | 0.659 | **0.747** | 0.862 |

凹形增长（越高越难涨）让稀有键"跳"从 0.222 提到 0.555；但**参数不能太凹**（pow=2 时掉回 0.234）。
