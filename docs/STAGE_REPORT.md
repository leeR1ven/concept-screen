# 阶段报告：马里奥"看画面→按键"（2026-11-05 ~ 11-06）

## 一句话

用 concept-brain 架构做"看画面→按键"：**能学会"跑/往右"（B 0.704），学不到可用的"该不该跳"（A 0.560，基线 0.80）**；固定随机中间层 + top-m 尾部是瓶颈，需要让中间层可学。

## 数据

| 项 | 值 |
|---|---|
| 原始数据 | 737,134 帧 / 280 局（其中通关 141 局、失败 139 局） |
| 使用 | **只用通关局**（失败局与"送死"数据不喂模型），每局末尾 30 帧丢弃 |
| 缓存 | `data/cache_win.npz`，**237,762 帧**，建缓存 110 秒 |
| 划分 | 前 70% 帧训练 / 后 30% 帧测试（**不同 episode 段**，无泄漏） |

## 最终数字（审计口径：episode 分离、m 现算、阈值全量标定）

| 键 | 模型（8×8） | 基线（永远猜多数类） | 判定 |
|---|---:|---:|---|
| right | 0.585 | 0.54 | 略超 |
| B（跑） | **0.704** | 0.82 | 低于基线 |
| A（跳） | **0.560** | 0.80 | 明显低于基线 |

三种子复现：right ±0.006、B ±0.018、**A ±0.002**（稳定）。

## 排除掉的原因（每条都有数字）

| 假设 | 实验 | 结果 |
|---|---|---|
| 数据不够 | 1% → 全量 237,762 帧 | 曲线从"不涨"变为单调上升，**成立但不够** |
| 缺统一降权 | 加凹形降权 + 弱连接删除 | 曲线从"先升后降"变单调上升 ✅ |
| 权重被 ±1 硬裁剪 | 改按列归一化 | B 0.684 → **0.792**（同批口径）✅ |
| 训练量不够 | 8×8：30 轮 vs 300 轮 | 0.793 vs 0.798，**已饱和** ❌ |
| 分辨率太低 | 8 / 16 / 24 对照 | 0.794 / 0.686 / 0.655，**越高越差** ❌ |
| 容量不够 | 16×16 + n4 2048 + m 512，300 轮 | B 0.740、right 0.500，**无改善** ❌ |
| top-m 太稀疏 | m 128 → 256 | 三项一字未变 ❌ |
| 缺几何特征 | 加"脚下左右 3 格地面" | A 0.600，略好仍不足 ❌ |
| 稀有键被淹没 | 正样本加权 3/6 倍 | A 最多 +0.02，B 下降 ❌ |

## 我犯的方法错误（都已改正，记录在案）

1. **拿 1~2% 数据下结论**（2,547 帧就断言"学不会"）；
2. **边跑后台训练边测性能** → 误报 27.96ms（实际 12.67ms）；
3. **只读一次滞后的任务输出** → 误判"并行拖慢 10 倍"；
4. **评估与训练同批数据** → 数字虚高 9 个点（0.793 → 0.704）。

## 成立的结论

1. 架构可搭：温度计编码 → 局部随机层 → top-m → 一条赫布规则（协方差 + 凹形增长 + 统一降权 + 列归一化）；
2. 学"频繁、局部、即时"的映射（跑/往右）可行；
3. 在合成闭环世界里（坑/障碍/移动敌人），用**宏动作 + 情境门控**能做到 60% 通关（固定关卡）——但换成随机布局后掉到 6%，说明那是"背关卡"；
4. 工程上：批处理把训练提速 170 倍；缓存让迭代从 38 分钟/轮降到 4.7 秒/轮。

## 不成立的结论

**在这套"固定随机中间层"实现下，学不到可泛化的"该不该跳"，因此不能真正通关。**

## 下一步（按优先级）

1. **让中间层可学**（架构允许：中间层可分裂/成长）。现在中间层是纯随机的，等于让线性读出直接啃原始编码——这是最可能的突破口；
2. **先做自监督预训练**（学"下一帧"），再冻结中间层学按键；本仓库已有 `p78_batched.py` 的批处理骨架可直接复用；
3. **把"该跳"变成分类问题而非回归**（离坑远/中/近三档），避开线性读出对连续量的弱点。
